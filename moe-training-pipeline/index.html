§0核心结论

直接回答：Max 的完整预训练不能被"省掉"，但也不值得为了省它而设计流水线。在本报告假设下，Max 的预训练只占系统总算力的 ~11%（7.2e24 对 6.7e25 FLOPs），而 Ultra 生长能否兑现 token 效率，其不确定区间宽达 1.2e25（系统的 ~17%）。真正的杠杆是：Ultra 的生长效率、后训练成本（2026 年已超过预训练的 10%）、日历并行，以及 Max 的最终质量。

推荐组织方式是"一条主干、三次承接"：Ultra 的第一生长阶段就按 Max 的形态训练，Max 在该阶段末（WSD 稳定期、未退火）分叉出去独立完成预训练（承接权重）；Max 的退火/中期训练用 Ultra 在同一批数据上前向时顺带捕获的 logits 做蒸馏退火（承接分布）；Max 的后训练以 Ultra 输出做 off-policy SFT 冷启动，再从 Ultra 最终 RL checkpoint 做 OPD（承接策略）。剪枝/嵌套派生 Max 没有任何 10× 压缩的公开证据，不作为主路径。

两条适用边界（详见 §7–§9）。上面的结论以 Max ≈ 1T / 40B、单版本为前提。若 Max 放大到 3–4T / 100 多 B 激活，Ultra:Max 从 10× 降到 2.7×：Max 预训练升至系统算力的 25%，预训练蒸馏进入最优师生比区间，剪枝/嵌套派生进入证据范围（算力为独立预训练的 1/9–1/40），并行训练第一次出现真实的资源争用——方案 D/E 从"否"变为可行备选（§7）。若版本持续迭代，"不做全程协同蒸馏"只在单版本内成立：Max v(n) 可全程蒸馏自已成熟的 Ultra v(n−1)，加上阶段错峰与主干延续，年算力约省 20–25%（§8）。

推荐流水线要点

  1. Ultra 三阶段生长，而非纯"扩层"。S1 = Max 形态（≈1.3T/46B）→ S2 深度插值（interposition）×2 → S3 专家数 ×4。10× 总参不可能只靠加层得到：深度每翻一倍，每 token 激活 FLOPs 同步翻倍，而前沿 10T 级设计点的激活比只有 2–4%；证据也显示深度是回报最高的生长算子，但应 ≤2× 且在专家扩增之前 [Du 2024; Wang/MSRA 2026]。d_model、注意力配置、专家粒度 d_expert、共享专家、词表、位置编码从第一天固定，只生长专家数与（有界的）深度。
  2. 每次生长都在 WSD 稳定期、从未退火的 checkpoint 出发；拷贝层时连同 Adam 矩一起拷贝、不重置全局 LR、仅对新参数做数百步 re-warm；专家复制加 ~1% 噪声并同时扰动 router 行、新参数的优化器状态清零、aux-loss-free 偏置归零。生长后的新增 FLOPs 至少不低于此前沉没成本 [Wang/MSRA 2026]。
  3. Max 在 S1 末分叉。分叉只为 Max 省下 ~5% 的 tokens（S1 的 1.5–2T），真正的收益是：一套 scaling-law/超参搜索与数据流水线、S1 本身就是对 Ultra 配方的全尺寸去风险化、同源分布使后续 KD 与 OPD 的初始 KL 更小（OPD 的失败案例几乎都源于分布距离而非尺寸比）、更高的投机解码接受率 [Yano 2026]。
  4. 不做全程协同蒸馏（单版本内）。日历上 Ultra 在大部分时间里并不比 Max 强（S1/S2 阶段它就是 Max 大小；S3 早期 loss 高于已训完的 Max），而不成熟 teacher 的在线 logits 会显著伤害学生（−21%）[Peng/Zhipu 2024]。只在 Max 的退火/中期训练（3–5T 高质量 tokens）阶段做 KD 退火：logits 来自 Ultra 自己在同一份退火数据上的前向（额外算力≈0），采用重要性采样 ~12 个样本/token（≈36 B/token，5T tokens ≈ 180 TB），α 走 WSD-α 调度、峰值 ≤0.9，低熵 token 回退硬标签；teacher checkpoint 按 loss 比值而非"最新"选择，以控制 10× 容量差。
  5. 后训练按 2026 主流组织。Ultra：SFT → 领域×努力度 RL 专家 → 多教师 OPD（MOPD）统一 [Kimi K3; DeepSeek-V4; Nemotron 3 Ultra]，预算按预训练的 10–20% 规划 [DeepSeek-V3.2]。Max：Ultra 双模式输出 off-policy SFT 冷启动 → 从 Ultra 最终 RL checkpoint（或其专家池）OPD → 轻量 RLVR/RLHF → 可选跨阶段 OPD 修复 [Qwen3 2025; GLM-5 2026]。OPD 中 Ultra 的前向开销可忽略（100B 学生 token ≈ 6e22 FLOPs），Qwen3 报告 OPD 仅需 RL 流水线 1/10 的 GPU 小时且效果更好。
  6. 算力与日历。系统总算力 ≈ 4.8–6.3e25 FLOPs，相对"两条独立预训练 + OPD"的 6.7e25 节省 6–28%，幅度几乎全部取决于 Ultra 生长是否兑现 G_stack 级别的 token 效率（区间下沿假设 token 中性，若出现饱和则节省归零）。Max 的全部预训练可以放在 ~10% 的集群切片上与 Ultra 并行，完全不在关键路径上；Max 的发布时间由 Ultra 后训练完成时间决定（约 Ultra 发布后 3–4 周），除非走"双轨"先发 Max-preview。
  7. 承诺前必须跑 proxy 阶梯（如 10B→20B→80B 的同构三阶段 MoE，含从头训练对照），验证：生长后的 loss-gap 是否随 token 收敛（饱和风险）、S1 分叉的小模型是否不弱于同算力独立训练、KD 退火相对纯退火的增益、OPD 冷启动后初始 per-token KL 是否 ≤0.05–0.1。

三大风险

  • 生长饱和。Liew & Kato（2025，arXiv:2510.06548）拟合的法则说阶段二的 scaling 指数随基模型 tokens 对数衰减，按字面外推，10T 模型在不到 1T 阶段二 tokens 后从头训练就会反超；Du et al. 与 Q Labs（2026-09）则给出相反证据（生长抬高 scaling 指数）。两边都是 ≤7B 规模的外推，必须自测。
  • 10× 师生差距。预训练蒸馏的最优 teacher 约为学生 2.5×（ACL 2025 杰出论文）、Zhipu 发现 32B teacher 对多数学生不如 9B；OPD 中一个分布距离大的更强 teacher 曾让学生归一化得分从 0.937 崩到 0.600。缓解手段存在（checkpoint 选择、α 调度、SFT 冷启动、优势裁剪）但都未在 1T 学生上验证。
  • 没有先例。截至 2026-10，没有任何实验室公开过万亿级的尺寸生长或 upcycling；Tele-FLM-1T 在 1T 尺寸只训了 15.7B tokens 且无评测；唯一的前沿 MoE 协同蒸馏 teacher（Llama 4 Behemoth）从未发布。本设计将是首例，需要为"生长不兑现"保留退路（S1/S2 的 tokens 本就只占 ~15%，即使 S3 退化为准从头训练也只损失这部分）。

四个结论性的边界

  • 算力边界。Max 预训练是 Ultra 的 13%；加上后训练后占系统 ~11%。即便把 Max 的预训练压到零（现有证据做不到），系统算力也只降 11%，低于生长不确定带的宽度（~17%）。所以流水线设计的目标函数应是"Max 质量 + Ultra 生长效率 + 日历"，而不是"少训一个模型"。
  • 时间边界。以 5 万张 GB300 级 GPU、每卡 1–1.5 PF 有效吞吐（FP8 稠密峰值 5 PF 的 20–30%，与 Megatron-Core 在 GB300 上对 DeepSeek-V3 报告的 1,233 TF/卡一致）计：Ultra 5.4e25 ≈ 8–12 天纯计算，考虑可用率、退火、长上下文与故障，现实 1–2 个月（与 36Kr 的"5 万 Blackwell × 1 个月"、字节 10T 传闻的"3 万卡 × 3–6 个月"同量级）；Max 7.2e24 ≈ 1–2 天纯计算，放在 10% 切片上约 3–6 周。Max 从来不在关键路径上。图 2 的日历排程比这些纯算力下限保守 3–4×，以覆盖生长门控暂停、小阶段的批大小限制、长上下文与排障。
  • 质量边界。Max 能超过"同算力独立训练"多少，取决于三次承接各自的增益：分叉（Yano 等：家族成员 ≥ 独立训练，省 25–31% 总算力，但那是 1B→8B 的 dense）、KD 退火（≤10B 规模 +5–10% 平均分、随 tokens 衰减至 +1–3 分）、OPD（Qwen3 8B：AIME24 74.4 对 RL 的 67.6）。没有一项在 1T 学生上测过。
  • 证据边界。生长、upcycling、KD、嵌套训练的全部受控证据都在 ≤70B 总参（MoE）/ ≤12.6B（dense）以内；万亿级实践只有"时间上的分叉"（K2→K2.5、V3→V3.1→V3.2、Ling 2.0→2.6）和"同配方独立预训练各尺寸"（Ling 2.0、Qwen3、V4 Pro/Flash）。

§2证据综述

4.4 三次承接的具体配方

① 分叉（权重）

  • 时点：S1 稳定期末、衰减之前（K2.5 也是从"接近末尾"的稳定期 checkpoint 分叉）。Max 分支拷贝全部权重与优化器状态，继续同一 LR 调度与数据流水线，但按 Max 的 scaling-law 调整批大小/峰值 LR（Ling 2.0 表 1：16B→1T 的 LR 3.36e-4→1.86e-4、批 4,400→18,144）。
  • Max 继续 ~28T tokens；它的 WSD 衰减与长上下文阶段 推迟，稳定期可持续到 Ultra S3 明显领先为止（稳定期多训几百 B 高质量 token 没有坏处，且 Max 不在关键路径）。
  • 收益核算：省 ~5% tokens；省一套 Max 尺寸的 scaling-law 与超参搜索（这部分并不便宜：DeepSeek-V3 的消融/实验算力被估计为正式训练的 2–4 倍 [Lambert]；Ant 用 500M–8B 的 "Ling 风洞" 预测 1T 行为，成本仍约为传统消融的 35%）；S1 的 loss 曲线直接验证 Ultra 的数据与配方。

② KD 退火（分布）

  • 门控：仅当 Ultra 某 checkpoint 在留出集上的 loss 低于 Max 当前 loss 一个预设裕度（proxy 上标定 d₁）时才启用；Zhipu 的 −21% 来自早期 teacher，−4% 来自 teacher 自己训练后 1/4 段的在线 logits。
  • 数据与存储：Max 的退火/中期训练数据（3–5T，高质量、推理密集、含长上下文）与 Ultra 退火数据同源；Ultra 在其退火前向中写出重要性采样目标（N=50 次抽样 → ~12 个唯一 token，3 B/样本 ≈ 36 B/token），5T tokens ≈ 180 TB；朴素 top-k 有偏，不用。若 Ultra 的退火数据与 Max 的不完全重合，差集用固定 Ultra checkpoint 离线打分（每 T token ≈ 6e23 FLOPs）。
  • 损失：前向 KL / 采样 token 上的 CE，τ=1；α 走 WSD-α（前 10% 线性升到 ≤0.9，稳定，末 1% 余弦归零）；teacher 熵最低的 ~15% token 回退硬标签以保 ICL；可在高熵 token 上提高 KD 权重。
  • teacher 选择：以 L_T/L̃_S 比值选 Ultra checkpoint（不一定是最新/最终），作为无需另训"助教"的容量差旋钮；Gemma 3 的"长视界下大 teacher 反而更好"是支持最终用最强 teacher 的唯一证据。
  • 预期：≤10B 规模证据为 +1–10 分（随 tokens 衰减）、pass@k 更持久；必须以 proxy 消融（纯退火 vs KD 退火，同 tokens）决定是否保留——Apple AFM 在续训阶段未见增益。

③ OPD（策略）

  • 前置：Ultra 完成 SFT → 领域×努力度 RL 专家 → MOPD；Max 用 Ultra（含各专家、各努力度/模式）的输出做 off-policy SFT 冷启动（Qwen3 第一阶段；Rethinking-OPD 的 ~200K rollouts 量级），目标是把初始 per-token KL 压到 ~0.05（MOPD 同源 0.04 稳定、外源 0.19 崩溃）。
  • OPD 本体：采样 token 的 sg[log π_Ultra − log π_Max] 作逐 token 优势，PPO/GRPO 代理 + IcePop 截断 IS；批 1,024–2,048 prompt × 1 rollout；优势裁剪 A_max≈5 或 sign·log(1+|Δ|)；响应长度上限 8–16K（teacher 优势在 16K 前缀衰减到 +0.02）；高熵 token 混入前向 KL 保 pass@k；MoE 需 R3 路由回放；teacher 用 Ultra 最终 RL checkpoint，或直接复用 Ultra 的专家池做多教师（每 prompt 单 teacher，避免梯度抵消 [GLM-5]）。
  • 系统：Ultra 作为独立推理服务异步 prefill 打分（权重 FP8 ≈10 TB、FP4 ≈5 TB，专家按需加载），池规模按与 Max decode 吞吐匹配配置；每轮 ~1–20B 学生 token，算力可忽略；两轮 OPD 的第二轮边际收益小，但 Ultra 后续升级时重跑 OPD 很便宜（K2 系列每 2–3 个月一个点版本）。
  • 之后：轻量 RLVR + 奖励模型 RL（OPD→RL 优于 SFT→RL 与联合目标）；可选 GLM-5 式跨阶段 OPD 修复遗忘；验证指标用任务成功率而非与 teacher 的一致度。

可选"双轨"：先发 Max-preview

若产品需要 Max 早于 Ultra 发布，Max 在第 14–19 周按 V4-Flash 模式走自己的"专家 → OPD → 统一"后训练并发布 preview；Ultra 完成后再做一次 Ultra→Max 的 OPD 升级（成本低、可重复）。代价是多一套 Max 尺寸的 RL 流水线（约 Max 预训练的 10%，7e23）。

§6待验证的开放问题

  1. 生长优势的渐近行为在 ≥100B MoE、≥1T tokens 上未被测过；Du（持续）与 Liew–Kato（饱和）互相矛盾且都只拟合到 ≤7B。G1 是本设计最重要的实验。
  2. 一次 ×4 还是两次 ×2 的专家扩增：Du 在深度上发现一次到位更好，EMO/Amazon 只测过 ×2；MoE 专家数上没有 ×4 单步的数据。
  3. 生长轨迹中间 checkpoint 作为独立模型的"质量税"从未与同算力专门训练的模型对照过（Yano 最接近，但是 dense ≤8B）。
  4. MoE 师生对的容量差：总参比 10×、激活比 ~7×，Apple 法则与 Zhang 法则都只在 dense 上成立；d₁ 必须自测。
  5. ≥10× 同族 OPD没有受控研究（TRL 的 235B→4B 为非正式实验，GPQA 在第 40 步后掉 10%）。
  6. 深度生长后的路由稳定性（熵、MaxVio、专家坍缩）无人测量；深度生长对长上下文与指令跟随的影响无证据。
  7. Muon/MuonClip 与生长步的交互只在 ≤7B 上有数据（Bu、SPARKLING）；μP 跨深度生长的迁移无文献。
  8. 万亿级 KD 退火的实际 I/O 与吞吐（Gemini 只给了定性说法）。

若长期打算走派生，S2/S3 的形状应为"切回"而设计：让 S3 相对 S2 的专家扩增恰好是 ×2（而非 ×2.7），切回时只需移除 50% 专家（REAP 在 Qwen3-Coder-480B / Kimi-K2 上验证近无损的比例；75% 已崩）。例如 S2′ = 72 层 × 512 专家 × top-12 ≈ 3.7T/100B，S3 = 96 层 × 1024 专家 × top-24 ≈ 10T/250B：切回 = 去掉一半专家 + 25% 深度（Star Elastic：15% 深度削减保留 95%；Minitron 深度剪枝需蒸馏恢复）。

单版本的三个资源结论

  • Max-S 不争资源，Max-L 争。1T Max 的全部预训练可以藏在 10% 切片里；3.7T Max 要么拿走 ~1/4 集群并把 Ultra 推迟 2–3 周，要么放弃并行、改为派生。
  • Ultra 的预训练池在第 12 周后就空了。后训练（SFT、RL 专家、MOPD）是推理密集、份额 25–40% 的阶段，不需要预训练池的互联形状——这是把下一代预训练接进来的物理基础，也是把 RL 搬到推理池/异构卡的理由。
  • Max 的发布时间与它的预训练无关，只与 Ultra 后训练何时完成有关（第 23 周 Ultra 发布 → 第 27 周 Max 发布）。要让 Max 先发，只能走"双轨"（Max 自己的专家→OPD 流水线先发 preview，Ultra 完成后再重跑一次 OPD）。

§8多版本：两种尺寸的流水线有多少交织空间

交织带来的六项优化

  1. 跨代 teacher 消除时序与容量差两难。单版本里 Ultra 不是太晚就是太强；跨代后 Max v(n) 可以像 Gemma 2/3、Gemini Flash 那样全程蒸馏自一个已经完成后训练、loss 已知的 Ultra v(n−1)，teacher checkpoint 按 loss 比值选、logits 一次写出多代复用（Apple 法则中"teacher 被多个学生摊销"是蒸馏最划算的情形）。对 Max-L（2.7×）这正是最优师生比；对 Max-S（10×）则用 Ultra v(n−1) 的中间 checkpoint 作"助教"。
  2. 阶段错峰把预训练池填满。Ultra v(n+1) 的预训练大块在 v(n) 退火结束的第 12–13 周接入，与 v(n) 的 SFT/RL/MOPD（推理密集，25–40%）重叠；图 6 中第 13 与第 28 周两次接入使总占用率维持在 85–100%，而不是单版本里第 12 周后的 60% 空闲。
  3. 主干延续代替从头。架构不变时 Ultra v(n+1) = 续训/生长 v(n)（K2.5 从"近末 K2 checkpoint"续训 15T；V3.2 用 ~1T tokens 完成 DSA 迁移；Ling 2.0→2.6 架构迁移预训练），算力按从头的 30–100% 计；只在架构大改（K2→K3、V3→V4）时重启生长阶梯——此时 S1/S2 分叉模式重新出现。用户的"分阶段生长"前提在多版本下自然延伸为跨代生长：10T→15T 可从 10T 生长而非从头。
  4. 两类资源池。预训练池（NVLink/大 EP、FP8/FP4）被连续的 Ultra 预训练占满；推理池（rollout、teacher 打分、OPD、数据合成、点版本）承接所有斜纹阶段，可用推理卡或国产卡。DeepSeek-V3.2 "后训练 >10% 预训练算力"意味着推理池不再是零头。
  5. Max 的血统策略。架构不变：Max v(n+1) 续自 Max v(n) 主干 + 全程 KD ← Ultra v(n)，再 OPD ← Ultra v(n+1)；架构换代：从新 Ultra 的 S1/S2 重新分叉以保持同源（OPD 初始 KL 小）。血统漂移是续主干的隐性代价，每两代重新分叉一次是保守做法。
  6. 点版本 = 重跑 OPD。Ultra 每出一个专家池升级，Max 的对应点版本只需 1–20B 学生 token 的 OPD（Qwen3：1/10 RL 的 GPU 小时），这是 K2 系列 2–3 个月一个点版本节奏在 Max 侧的低成本复制。
